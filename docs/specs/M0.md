## M0-T1 — Spike: web_core under Hermes/Metro (go/no-go)

- **Goal:** prove `@a2ui/web_core` 0.10.x runs in a React Native runtime. Decides ADR-0001.
- **Files:** `apps/example/` (temporary spike screen, delete after), `packages/react-native-a2ui/package.json` (add dependency).
- **Do:** install web_core in the library package; in the example app, import it, feed it 2-3 official example messages (hardcoded), log resulting tree + data model to console. Run on Hermes via Expo Go or simulator. Also check: does its function registry ship `required`/`email`?
- **No formal tests** (spike). **Exit:** documented go/no-go in STATUS.md + ADR-0001 status updated; list of any polyfills/quirks found. If NO-GO: open fallback task (vendored fork) before proceeding.

## M0-T3 — `ProtocolEngine` interface + `A2uiEngine` adapter

- **Goal:** the modularity boundary (ADR-0005), real.
- **Files:** `src/engine/types.ts`, `src/engine/a2ui/A2uiEngine.ts`, `src/engine/a2ui/A2uiEngine.test.ts`.
- **Test-first (Vitest):** happy path — process a `createSurface` + `updateComponents` batch → `getSurface().getNode('root')` returns the tree; `updateDataModel` → subscribed pointer callback fires with new value. Edge cases — malformed message in a batch (rest still processed, error reported), unknown surfaceId (no throw), `deleteSurface` (handle gone, subscriptions dead), value write → outbound message emitted.
- **Exit:** adapter ≤ ~300 lines; all tests green; interface documented with JSDoc.
